# CleanTempMail Workspace 优化调研（2026-10-22）

调研方式：代码审查（全部源码，含 5 万封模拟邮件的 SQLite 查询计划分析）、浏览器界面走查（桌面/手机/深色、axe 无障碍扫描、键盘遍历）、Cloudflare Email Service 文档调研。

## P0 必修：可靠性与安全

| # | 问题 | 位置 | 后果 | 修法 |
|---|---|---|---|---|
| 1 | 收信解析/写库失败时没有兜底 | `src/mail.ts:73-127` | 大邮件在免费套餐 CPU 超时、畸形 MIME、D1 报错时，邮件**静默丢失**（R2 有原文但没有记录） | 解析包 try/catch，失败时用信头建一条兜底记录并关联原文 |
| 2 | References 过长 | `src/mail.ts:35-38` | 邮件列表的长会话超过 D1 每条查询 100 个参数上限 → 收信失败，同样丢信 | 只取 In-Reply-To + 最近 20 个引用 |
| 3 | 超过 100 封的会话 | `src/routes/messages.ts:107,127` | 只取到最早的 100 封，「回复」会回到旧邮件上；标已读范围也不对 | 倒序取最新的再反转；只标记实际返回的 id |
| 4 | 批量操作 >100 个会话 | `messages.ts:181`、`list.js` | 全选后批量归档/删除直接报错回滚 | 分块（≤90）+ `DB.batch` |
| 5 | 内嵌图片 cid 前缀误替换 | `messages.ts:262-264` | `cid:img1` 会把 `cid:img10` 也替换掉，图片显示失败 | 精确匹配 cid 后面的分隔符 |
| 6 | 一键配置的顺序风险 | `src/provision.ts:175-189` | 先删旧 MX 再开 Email Routing，若开启失败域名将收不到任何邮件；原 catch-all 规则被覆盖且未备份 | 先开启路由再删 MX；备份原 catch-all，移除域名时恢复 |
| 7 | 同主域 CSRF | `src/auth.ts` | 公开站与本应用同属 cleantempmail.com，`SameSite=Lax` 挡不住同站请求；`req.json()` 不校验类型，可被构造请求发信/改设置 | 校验 Origin + 强制 `application/json`，Cookie 改 `__Host-` 前缀 |
| 8 | 反向标签劫持 | `reader.js` iframe | 邮件里的链接可通过 `window.opener` 把本页跳到假登录页 | `_headers` 加 `Cross-Origin-Opener-Policy: same-origin` |
| 9 | OAuth token 并发刷新 | `auth.ts:166-179` | 每个请求（含 30 秒轮询）都可能刷新；并发刷新可能互相作废，导致域名管理失效 | 只在需要调 Cloudflare API 时刷新，带条件更新；失效后不再重试 |
| 10 | 新写信窗口：签名被当成内容 | `compose.js` isEmpty | 打开写信什么都没写就关闭 → 存一份只有签名的空草稿；舍弃时误弹确认 | 以「是否修改过」判断 |
| 11 | 写信窗口关闭时上传中的附件丢失；撤销发送边缘情况 | `compose.js:466-471,551,646-679` | 附件成孤儿；撤销按钮淡出期间仍可点；倒计时中关页面不会发出也不提示 | 关闭前等待上传；淡出时禁用按钮；倒计时中拦截关页 |
| 12 | 重复投递去重不严 | `mail.ts` | 无 Message-ID 的邮件和并发重投会产生重复 | 部分唯一索引 + `INSERT OR IGNORE` |
| 13 | 发出后保存失败 → 用户重发产生重复 | `compose.ts:240-255` | 对方收到两封 | Resend 加 Idempotency-Key；区分「已发出但未保存」 |
| 14 | 会话归类 | `mail.ts:42-49,167`、`compose.ts:220` | 不同发件人的同名「Re: 发票」被并成一个会话；Resend 发出的邮件没有 Message-ID；回复自己发的邮件不带线程头 | 自己生成并保存 Message-ID；主题兜底要求参与人重叠 |
| 15 | 机密存放 | `util.ts`、`auth.ts` | 加密密钥与密文同在 D1；会话 id 明文存储；过期会话不清理 | 密钥改用 Worker Secret；存会话 id 哈希；定时清理 |

## P1 性能：邮件量上来后会出问题

5 万封邮件时，会话列表每次约 370ms、几乎全表读取；侧栏统计每 30 秒全表聚合一次，**单个打开的标签页每天约 1.4 亿行读取，D1 免费额度是每天 500 万行**。

- 新增 `threads` 汇总表（最后时间、计数、标记）+ 计数器表，列表和统计都走索引
- 轮询只查最新时间戳，后台标签页降低频率
- FTS5 全文搜索：现在只能搜到正文前 160 字；支持 `from:` `to:` `has:附件` `before:` 等搜索语法
- 联系人表（现在每次按键都全表扫描）
- 会话详情不再返回 HTML 正文（iframe 会单独加载），减少 R2 读取，避免长会话超出免费套餐 50 次子请求上限
- 清空垃圾箱/定时清理按已知 key 批量删除（现在可能超出子请求限制并卡住）
- 发送前用 R2 `head()` 检查附件大小，避免大附件撑爆 128MB 内存

## P1 体验与外观细节

- **写信发件人栏**：桌面端地址右对齐、显得空；手机上域名溢出盖住下拉箭头
- **无障碍**：列表行无法用 Tab 聚焦；浅灰文字（分组标题、侧栏小标题）对比度不达标；深色模式「写邮件」按钮白字对比度不足；编辑器、收件人输入框缺少可访问名称
- 离开邮件页面时搜索框文字残留
- 批量操作栏两个星标图标含义不清
- **发件人头像**：用发件域名的品牌图标（经 Worker 代理获取并缓存，不暴露你的 IP），列表辨识度大幅提升
- **新闻邮件一键退订**（解析 List-Unsubscribe）
- 手机：左右滑动归档/删除、下拉刷新；写信时提示条避开发送按钮
- 可拖拽调整列表宽度；阅读窗格可切换（右侧/关闭）
- 收件箱清空时的完成插图

## P2 新功能（按价值排序）

1. **Catch-all 防垃圾**（最重要）：catch-all 会吸引大量字典攻击式垃圾邮件
   - 一键**停用某个地址**（以后直接 SMTP 拒收，适合泄露的别名）
   - 屏蔽发件人/域名、垃圾邮件箱
   - 可选 Workers AI 判定（Cloudflare 官方有 spam-filtering 示例，数据不出 Cloudflare）
2. **投递状态**：已发送邮件显示「已送达 / 退信 / 被拒」（GraphQL `emailSendingAdaptive`）；自动识别退信通知并关联原邮件；管理 Cloudflare 抑制列表
3. **地址管理页**：所有用过的地址、备注、颜色、通知开关、停用
4. **规则**：按收件地址/发件人自动打标签、归档、星标、转发
5. **标签**（一封邮件多个标签）
6. **定时发送、稍后提醒**（Durable Object alarm）
7. **Web Push 推送**：关掉页面也能收到新邮件通知；PWA
8. **AI 助手**（Workers AI）：会话摘要、翻译、智能回复草稿
9. 模板 / 快捷回复
10. **团队成员**：邀请成员，按域名/地址分配权限（名副其实的 Workspace）
11. 导出备份（eml/mbox）、存储用量统计
12. 域名健康检查（SPF/DKIM/DMARC 一键修复）、DMARC 报告
13. 英文界面

## 已确认良好
